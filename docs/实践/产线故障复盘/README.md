## 共性根因归纳

从 7 篇案例中可提炼出以下五类共性根因，排查产线故障时可优先对照：

### 1. 内存配置类问题频发

- **容器内存与 JVM 堆配置不一致**：pod 内存 limit 等于或不足 JVM 堆 + 系统开销，触发 OOMKiller（见 [容器与JVM内存配置不一致致OOMKiller](md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）
- **堆内存溢出**：大结果集或未分页接口返回数据堆积，撑爆堆内存（见 [大结果集致堆内存溢出](md/OOM/大结果集致堆内存溢出.md)、[下游接口未分页致OOM](md/pod重启/下游接口未分页致OOM.md)）

### 2. 大请求/大数据量查询是常见触发因子

- 下游接口"有分页参数"但未实现真分页，全量查询堆积，是本案例库中出现最多的根因（三起事故，见 [下游接口未分页致OOM](md/pod重启/下游接口未分页致OOM.md)）
- 新增接口未评估单次返回数据量，缺少分页/上限保护（见 [大结果集致堆内存溢出](md/OOM/大结果集致堆内存溢出.md)）
- 月初/周期性大数据查询（导报表）未提前扩容或限制数据量（见 [下游接口未分页致OOM](md/pod重启/下游接口未分页致OOM.md)）
- 数千 ID 参数的大请求未分批处理（见 [容器与JVM内存配置不一致致OOMKiller](md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）

### 3. 健康检查与资源限制的耦合

- liveness 超时是表象，需追查"为什么响应慢"：内存压力、大数据量、下游未分页才是根因，避免误判为探针阈值问题（2026-04-01 曾误判为 GC 停顿，实为下游未分页，见 [下游接口未分页致OOM](md/pod重启/下游接口未分页致OOM.md)）
- OOMKiller 触发后次生效应（如连接池雪崩）需纳入预案（见 [容器与JVM内存配置不一致致OOMKiller](md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）

### 4. 发布/构建流程的副作用

- SNAPSHOT 版本 + mvn install + jenkins 服务器共用 → 本地仓库内容被覆盖但版本号不变，依赖方拉到漂移内容（见 [SNAPSHOT与mvn-install覆盖本地仓库](md/依赖异常/SNAPSHOT与mvn-install覆盖本地仓库.md)）

### 5. 连接池与并发控制

- 白天手动操作生产库致锁表，异步写日志线程连接等待堆积，超过连接池上限（见 [数据库锁表致连接池耗尽](md/连接超时/数据库锁表致连接池耗尽.md)）
- 重启后获取连接代码未加锁，并发请求超过数据库连接数限制（见 [容器与JVM内存配置不一致致OOMKiller](md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）
