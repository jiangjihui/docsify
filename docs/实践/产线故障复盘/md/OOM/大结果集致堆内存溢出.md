# 大结果集致堆内存溢出

> **故障日期**: 2025-03-07
> **涉及服务**: 数据服务B
> **故障类型**: OOM

## 故障现象

2025-03-07 09:32:50~09:53:47（约 20 分钟），生产命名空间数据服务B 出现 OOM。数据服务告警群在 09:32:30 先期出现 4MB 响应体告警：上游调用方调用小时级数据查询接口时触发 Feign 异常（FeignException），异常堆栈中返回体大小约 66MB，请求路径指向数据服务B 内部小时级数据查询接口。

## 现场分析

- **日志线索**：在日志平台搜索关键字 `数据服务B容器 and error and "Java heap space"`，可快速命中 OOM 错误日志。
- **错误日志**：`java.util.concurrent.ExecutionException: java.lang.OutOfMemoryError: Java heap space`，在 Tomcat ContainerBase 线程中多次抛出，并伴随 "New heap file created" 信息。
- **受影响服务**：数据服务B，持续约 20 分钟。
- **dump 文件生成耗时**：566 秒，拖慢诊断与恢复节奏。
- **接口行为**：新增的开放接口允许查询全量数据，上游调用方一次查询了 2 年约 2 万+ 数据点小时级数据，单次返回数据量过大。
- **MAT 分析 hprof 关键发现**：Problem Suspect 1 占 3.9GB/4GB（97.54%），内存积累定位到 `org.postgresql.core.v3.QueryExecutorImpl.processResults`，结果集以 `java.util.ArrayList` 形式堆积在 `org.apache.tomcat.util.threads.TaskThread` 持有的 `java.lang.Object[]` 中，撑爆堆内存。

## 根因

新增开放接口未评估单次返回数据量，缺少分页或上限保护，允许一次查询 2 年约 2 万+ 数据点小时级数据。PostgreSQL JDBC 驱动在 `QueryExecutorImpl.processResults` 中将结果集一次性堆积为 `ArrayList`，占堆 97.54%（3.9GB/4GB），直接撑爆堆内存。

## 解决方案

- 限制接口查询全量数据，增加分页或上限保护，避免单次返回超大结果集。
- 对开放接口强制配置最大返回行数与时间范围上限。

## 复盘要点

- 新增开放接口未评估单次返回数据量，缺少分页/上限保护。
- dump 文件生成耗时 566 秒，影响诊断与恢复。
- 日志关键字 `数据服务B容器 and error and "Java heap space"` 可快速定位 OOM。
