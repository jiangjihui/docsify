# 数据库锁表致连接池耗尽

> **涉及服务**: 数据服务B + 多个受影响服务
> **故障类型**: 连接超时

## 故障现象
数据服务B 抛出 JDBC 连接超时：`HikariPool-1 - Connection is not available, request timed out after 30000ms`（`Failed to obtain JDBC Connection`）。超时持续约 1 分钟，但异常期间被缓存的返回结果作为脏数据影响了约 30 分钟。监控侧数据库 CPU 使用率飙升至 100%，接口响应时间被拉长至 9s。

## 现场分析
日志关键字检索 `数据服务B 容器名 and error and "Connection is not available"` 命中关键错误：

```
### Error updating database.  Cause: org.springframework.jdbc.CannotGetJdbcConnectionException: Failed to obtain JDBC Connection; nested exception is java.sql.SQLTransientConnectionException: HikariPool-1 - Connection is not available, request timed out after 30000ms.
```

监控侧观测到：
- 数据库 CPU 使用率达到 100%；
- 接口响应时间拉长至 9s；
- 受影响服务及持续时间：数据服务B 约 30 分钟、受影响服务1 约 30s、受影响服务2 约 30s。

根因线索：白天有手动 `update log 表字段` 操作，触发 log 表锁表、数据库 CPU 100%；数据服务B 的异步写日志线程在写 log 表时连接等待堆积，随请求增多等待连接数越积越多，最终超过 HikariCP `maximum-pool-size=30`，连接池耗尽、请求超时。

## 根因
白天手动 `update` log 表字段导致 log 表锁表、数据库 CPU 使用率 100%。数据服务B 的异步线程写入日志时需获取数据库连接写 log 表，锁表后写日志连接等待，随请求增多等待连接越积越多，最终超过 HikariCP 配置的 `maximum-pool-size=30`，连接池耗尽并抛出 30000ms 连接超时。异步线程池 `maxPoolSize=64` 大于数据库连接池上限 30，进一步加剧对主业务连接的抢占。

## 解决方案
- 避免白天操作生产数据库，DDL/批量更新需避开业务高峰。
- 日志改用 mq 异步落库，控制写日志线程数小于数据库连接池容量，避免抢占主业务连接；或将日志表拆分到非主业务库，降低耦合。
- 异常路径不缓存返回结果数据，避免脏数据残留 30 分钟。

## 复盘要点
- 手动 DDL/更新避开业务高峰，禁止白天操作生产库
- 异步写日志线程数与数据库连接池容量需匹配，避免抢占主业务连接
- 日志表与主业务库分离，降低耦合风险
- 异常路径不应缓存脏数据

## 关键命令与指标
```bash
# 日志关键字：数据服务B 容器名 and error and "Connection is not available"
# HikariCP maximum-pool-size=30；异步线程 maxPoolSize=64；DB CPU 100%；接口响应 9s
```
