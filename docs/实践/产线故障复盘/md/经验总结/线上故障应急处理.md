# 线上故障应急处理

> **类型**: 方法论/经验总结（非具体事故）
> **用途**: 产线故障复盘案例库的方法论入口，配合具体事故案例使用

## 核心方法论

故障复盘必须梳理完整时间线——故障发生时刻、报警发现耗时、介入处理时点、处理过程中各项操作（有效/无效）及其影响，时间点要求精确到秒。

复盘过程伴随"灵魂拷问"：
- 为何报警这么久才触发？
- 为何止血操作拖延确认？
- 为何出现大量无效操作？

正是这种拷问驱动查漏补缺与成长反思。

## 关键检查清单

故障复盘时需梳理以下要素（精确到秒）：
- 故障发生时间点
- 报警发现耗时（发生 → 告警的间隔）
- 介入处理时点（告警 → 人工介入的间隔）
- 处理过程中各项操作记录（操作内容、有效/无效、影响）

## 共性根因归纳

从"灵魂拷问"中可隐性归纳三类共性弱点：
- 报警延迟类：监控/告警阈值设置不当，或告警链路本身故障
- 止血确认迟缓类：止血操作效果未及时确认，导致后续操作拖延
- 无效操作过多类：缺乏系统化排查思路，盲目尝试

## 复盘要点

- 时间线必须精确到秒，拒绝模糊时间
- 每项操作须区分"有效/无效"并评估实际影响
- 直面三类灵魂拷问：报警为何延迟、止血为何拖延、无效操作为何频繁
- 痛苦的复盘过程本身就是查漏补缺与团队成长的契机

## 案例库共性根因（按故障域）

从已复盘的具体事故中归纳出五类高频根因，排查产线故障时可优先对照：

### 1. 内存配置类问题频发

- **容器内存与 JVM 堆配置不一致**：pod 内存 limit 等于或不足 JVM 堆 + 系统开销，触发 OOMKiller（见 [容器与JVM内存配置不一致致OOMKiller](实践/产线故障复盘/md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）
- **堆内存溢出**：大结果集或未分页接口返回数据堆积，撑爆堆内存（见 [大结果集致堆内存溢出](实践/产线故障复盘/md/OOM/大结果集致堆内存溢出.md)、[下游接口未分页致OOM](实践/产线故障复盘/md/pod重启/下游接口未分页致OOM.md)）

### 2. 大请求/大数据量查询是常见触发因子

- 下游接口"有分页参数"但未实现真分页，全量查询堆积，是本案例库中出现最多的根因（三起事故，见 [下游接口未分页致OOM](实践/产线故障复盘/md/pod重启/下游接口未分页致OOM.md)）
- 新增接口未评估单次返回数据量，缺少分页/上限保护（见 [大结果集致堆内存溢出](实践/产线故障复盘/md/OOM/大结果集致堆内存溢出.md)）
- 月初/周期性大数据查询（导报表）未提前扩容或限制数据量（见 [下游接口未分页致OOM](实践/产线故障复盘/md/pod重启/下游接口未分页致OOM.md)）
- 数千 ID 参数的大请求未分批处理（见 [容器与JVM内存配置不一致致OOMKiller](实践/产线故障复盘/md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）

### 3. 健康检查与资源限制的耦合

- liveness 超时是表象，需追查"为什么响应慢"：内存压力、大数据量、下游未分页才是根因，避免误判为探针阈值问题（2026-04-01 曾误判为 GC 停顿，实为下游未分页，见 [下游接口未分页致OOM](实践/产线故障复盘/md/pod重启/下游接口未分页致OOM.md)）
- OOMKiller 触发后次生效应（如连接池雪崩）需纳入预案（见 [容器与JVM内存配置不一致致OOMKiller](实践/产线故障复盘/md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）

### 4. 发布/构建流程的副作用

- SNAPSHOT 版本 + mvn install + jenkins 服务器共用 → 本地仓库内容被覆盖但版本号不变，依赖方拉到漂移内容（见 [SNAPSHOT与mvn-install覆盖本地仓库](实践/产线故障复盘/md/依赖异常/SNAPSHOT与mvn-install覆盖本地仓库.md)）

### 5. 连接池与并发控制

- 白天手动操作生产库致锁表，异步写日志线程连接等待堆积，超过连接池上限（见 [数据库锁表致连接池耗尽](实践/产线故障复盘/md/连接超时/数据库锁表致连接池耗尽.md)）
- 重启后获取连接代码未加锁，并发请求超过数据库连接数限制（见 [容器与JVM内存配置不一致致OOMKiller](实践/产线故障复盘/md/pod重启/容器与JVM内存配置不一致致OOMKiller.md)）
