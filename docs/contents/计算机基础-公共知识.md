## 进制与编码

### 进制转换

计算机中常用的进制：二进制（0b）、八进制（0）、十进制、十六进制（0x）。

| 进制 | 基数 | 数字符号 | 示例 |
| --- | --- | --- | --- |
| 二进制 | 2 | 0, 1 | 0b1010 = 10 |
| 八进制 | 8 | 0-7 | 012 = 10 |
| 十进制 | 10 | 0-9 | 10 |
| 十六进制 | 16 | 0-9, A-F | 0xA = 10 |

**快速转换技巧：**

- 二进制 ↔ 八进制：每3位二进制对应1位八进制
- 二进制 ↔ 十六进制：每4位二进制对应1位十六进制
- 二进制 → 十进制：按权展开求和，如 `0b1010 = 1×2³ + 0×2² + 1×2¹ + 0×2⁰ = 10`
- 十进制 → 二进制：除2取余，逆序排列

### 字符编码

| 编码 | 长度 | 说明 |
| --- | --- | --- |
| ASCII | 7bit | 128个字符，仅英文 |
| GBK | 1-2字节 | 中文扩展，兼容ASCII |
| Unicode | 2-4字节 | 统一字符集，覆盖全球文字 |
| UTF-8 | 1-4字节 | Unicode的可变长编码，兼容ASCII，Web主流 |

**UTF-8 编码规则：**

| Unicode 范围 | UTF-8 字节数 | 编码格式 |
| --- | --- | --- |
| 0x0000 - 0x007F | 1 | `0xxxxxxx` |
| 0x0080 - 0x07FF | 2 | `110xxxxx 10xxxxxx` |
| 0x0800 - 0xFFFF | 3 | `1110xxxx 10xxxxxx 10xxxxxx` |
| 0x10000 - 0x10FFFF | 4 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

> 中文通常占3个UTF-8字节。ASCII字符在UTF-8中仅占1字节，因此UTF-8对英文内容非常高效。

**int 与 long 的平台差异：**

- 16位系统：int 占2字节，long 占4字节
- 32位系统：int 占4字节，与 long 相同
- 64位系统：int 占4字节，long 占8字节（LP64模型，Linux/macOS）；Windows 下 long 仍为4字节（LLP64模型）

## 字节序

字节序（Byte Order）指多字节数据在内存中的存放顺序。

| 类型 | 说明 | 示例（0x12345678） |
| --- | --- | --- |
| 大端序（Big-Endian） | 高位字节存放在低地址 | 12 34 56 78 |
| 小端序（Little-Endian） | 低位字节存放在低地址 | 78 56 34 12 |

- **网络传输**使用大端序（网络字节序）
- **x86/x64** 架构使用小端序
- Java 的 `ByteBuffer` 默认大端序，可通过 `order(ByteOrder.LITTLE_ENDIAN)` 切换

## 位运算

| 运算 | 符号 | 说明 | 示例 |
| --- | --- | --- | --- |
| 与 | `&` | 两位都为1则为1 | `0b1010 & 0b1100 = 0b1000` |
| 或 | `\|` | 有一位为1则为1 | `0b1010 \| 0b1100 = 0b1110` |
| 异或 | `^` | 相同为0，不同为1 | `0b1010 ^ 0b1100 = 0b0110` |
| 取反 | `~` | 0变1，1变0 | `~0b1010 = 0b0101` |
| 左移 | `<<` | 低位补0，相当于×2ⁿ | `0b0010 << 2 = 0b1000` |
| 右移 | `>>` | 高位补符号位（算术右移） | `0b1000 >> 2 = 0b0010` |
| 无符号右移 | `>>>` | 高位补0（逻辑右移，Java特有） | `0b1000 >>> 2 = 0b0010` |

**常用技巧：**

- 判断奇偶：`n & 1`，结果为1是奇数
- 交换两数：`a ^= b; b ^= a; a ^= b;`
- 取最低位1：`n & (-n)`
- 置0某位：`n &= ~(1 << k)`
- 置1某位：`n |= (1 << k)`
- 判断某位：`(n >> k) & 1`

## 每个人都应该知道的数字

**典型操作所需的时长：**

| 操作 | 延迟 |
| --- | --- |
| L1 缓存引用 | 0.5 ns |
| 分支预测错误 | 5 ns |
| L2 缓存引用 | 7 ns |
| 互斥锁锁定/解锁 | 100 ns |
| 主内存引用 | 100 ns |
| 用 Zippy 压缩 1K 字节 | 10 μs |
| 通过 1Gbps 网络发送 2K 字节 | 20 μs |
| 从内存顺序读取 1MB | 250 μs |
| 同一数据中心内往返 | 500 μs |
| 磁盘寻道 | 10 ms |
| 从网络顺序读取 1MB | 10 ms |
| 从磁盘顺序读取 1MB | 30 ms |
| 加州↔荷兰 数据包往返 | 150 ms |

**关键要点：**

- 内存速度快，磁盘速度慢——磁盘寻道比内存引用慢约10万倍
- 网络传输成本高——跨数据中心延迟是同机房的三倍以上
- 压缩是划算的——用廉价CPU换回两倍网络带宽
- 全局共享数据成本高昂——锁竞争导致事务序列化，严重降低性能
- 为扩展写入进行架构设计，尽可能使写入并行
